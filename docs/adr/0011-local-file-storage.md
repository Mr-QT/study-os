# ADR-0011：本地文件存储（磁盘 + 元数据表）

- 状态：Proposed（已实现，待用户批准）
- 日期：2026-10-20
- 影响范围：文件上传/下载、备份、后续对象存储迁移
- 背景与问题：里程碑 1.3 需要真实文件能力。产品最终要支持对象存储与生命周期管理，但当前是本地优先、单实例开发阶段。

## 备选方案及证据

| 方案 | 优点 | 缺点 |
|---|---|---|
| 本地磁盘 + `file_assets` 元数据（选中） | 零外部依赖、可离线、实现简单 | 单实例、需自行备份；不能直接水平扩展 |
| MinIO / S3 兼容 | 接近生产、可扩展 | 增加服务依赖；阶段 1 尚未引入对象存储 |
| 预签名直传 | 减轻 API 负担 | 需要对象存储与额外鉴权链路 |

## 决策与理由

- 上传走 `POST /api/v1/files?spaceId=...`（multipart），限制单文件 10MB；
- MIME 白名单：PNG/JPEG/WebP/PDF/text/plain/text/markdown；
- 磁盘文件名使用随机 UUID + 扩展名，原始文件名只存数据库；计算 SHA-256 便于去重与校验；
- 元数据存 `file_assets`，下载前校验空间成员权限；
- 删除为软删除（保留磁盘文件，避免误删无法恢复）。

## 安全/隐私/性能/成本影响

- 路径穿越通过 `basename` + 随机键避免；
- 未做病毒扫描与图片解码校验，列入已知问题；
- 磁盘占用随上传增长，尚无配额与生命周期清理（属运维阶段）。

## 回退方案

新增 `StorageAdapter` 接口后可切换到 S3/MinIO；元数据表与 API 契约保持不变。
