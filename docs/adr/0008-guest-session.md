# ADR-0008：本地访客身份与签名 Cookie 会话

- 状态：Proposed（已实现，待用户批准）
- 日期：2026-10-20
- 影响范围：认证、空间归属、后续账号绑定
- 背景与问题：产品要求“无需账号即可本地使用”，同时后续要支持账号、设备与撤销。里程碑 1.1 需要最小可用的身份，让空间有真实归属和权限边界。

## 备选方案及证据

| 方案 | 优点 | 缺点 |
|---|---|---|
| 服务端会话表 | 可即时撤销、可审计 | 1.1 需额外表与清理任务 |
| 无状态 JWT | 无服务端状态 | 撤销困难、密钥轮换复杂 |
| 签名 Cookie 携带 user id（选中） | 实现最小、可随账号体系升级 | 撤销依赖后续设备表；签名密钥泄露影响大 |

## 决策与理由

- `POST /api/v1/auth/guest` 在一个事务内创建 `users` + 默认空间 + `memberships(owner)`；
- 会话 Cookie `studyos_session` 使用 `@fastify/cookie` 签名，`httpOnly`、`SameSite=Lax`、生产环境 `Secure`、30 天有效；
- 生产环境强制要求 `SESSION_SECRET`（至少 16 字符），开发环境使用明确标注的默认值；
- `GET /api/v1/auth/me` 返回用户与其空间；
- 权限：所有空间读写先校验 `memberships`，非成员统一返回 404，避免泄露资源是否存在（已用 IDOR 测试覆盖）。

## 安全/隐私/性能/成本影响

- Cookie 不包含角色信息，角色每次从数据库读取，撤销即时生效；
- 未实现 CSRF token，依赖 `SameSite=Lax` 与 JSON 请求；后续加入账号体系时补强；
- 访客身份仅存于该设备，清除 Cookie 即无法找回（符合本地优先，但需在 UI 说明）。

## 回退方案

升级为服务端会话表时，引入 `sessions` 表并以 session id 替换 Cookie 中的 user id，约 1 天。
