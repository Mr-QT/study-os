# ADR-0009：IndexedDB 空间缓存（Dexie）

- 状态：Proposed（已实现，待用户批准）
- 日期：2026-10-20
- 影响范围：`apps/web` 本地存储、后续 outbox 与同步
- 背景与问题：产品要求本地优先与离线可读。里程碑 1.1 需要先建立可靠的客户端存储基础，为 1.5 的 outbox/增量同步铺路。

## 备选方案及证据

| 方案 | 优点 | 缺点 |
|---|---|---|
| Dexie（选中） | 事务、索引、TypeScript 友好、体积小 | 增加一个运行时依赖 |
| 原生 IndexedDB | 零依赖 | 回调式 API 冗长，易出错 |
| idb | 轻量 Promise 封装 | 查询与版本管理较弱 |

## 决策与理由

- `apps/web/lib/local-db.ts` 定义 Dexie 数据库 `study-os`，v1 仅包含 `spaces` 表（主键 `id`，索引 `updatedAt`）；
- 每次成功加载空间后写入缓存；API 不可用时读取缓存并显示“离线缓存”提示，不伪造实时状态；
- 当前**只读缓存**：离线创建/修改与 outbox 属里程碑 1.5，本期不做，避免半成品同步逻辑。

## 安全/隐私/性能/成本影响

- 缓存只存空间元数据（名称、隐私级别、时间戳），不存笔记正文；
- 共享设备上缓存可被同一浏览器用户读取，需在隐私说明中披露；
- 数据量小，无额外性能压力。

## 回退方案

删除依赖并清除 `study-os` 数据库即可回退；后续切换 idb 不影响服务端契约。
