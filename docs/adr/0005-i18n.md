# ADR-0005：i18n 与本地化路由

- 状态：Proposed（待用户批准）
- 日期：2026-10-19
- 影响范围：`apps/web`
- 背景与问题：决策 36 要求中英双语 + 完整无障碍基础，但不做无限多语言。需要可静态生成、可扩展、无运行时依赖的方案。

## 备选方案及证据

| 方案 | 优点 | 缺点 |
|---|---|---|
| 语言前缀路由 + 本地字典模块（选中） | 零依赖、可静态生成、URL 可分享 | 新增语言需加字典与路由参数 |
| next-intl | 功能完整（复数、日期、消息格式） | 增加依赖与配置 |
| 运行时客户端切换 | 实现简单 | SEO/首屏语言不一致 |

- 决策与理由：路由形如 `/zh-CN`、`/en`，`app/[lang]` 作为根布局；词典在 `lib/i18n.ts` 中以 `satisfies` 约束两种语言结构一致；`/` 由 `next.config.ts` 重定向到 `/zh-CN`。语言切换使用普通链接，刷新后语言保持一致。
- 无障碍：设置 `html lang`、跳过导航链接、状态区 `role="status"` + `aria-live`、支持 `prefers-reduced-motion`；完整 WCAG 2.2 AA 审计留待后续里程碑（当前为 PARTIAL）。
- 回退方案：迁移到 next-intl 时可保留词典结构，预计 1 天。
- 需用户批准：是（批准记录：待补充）
