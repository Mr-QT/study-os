# 分阶段开发路线图与依赖关系

> **阶段是开发顺序，不是缩减最终产品范围。** 各阶段均需拆为可运行、可验收的小里程碑；未通过验收不得自动进入下一阶段。

| 阶段 | 目标 | 关键交付 | 退出条件 |
|---|---|---|---|
| 0 | 架构验证与项目初始化 | monorepo、Windows 脚本、Docker、CI、ADR、Design Tokens、基本健康检查 | 本地一键启动、类型检查和 smoke test 可运行 |
| 1 | **完整基础平台 + 核心学习闭环** | 账号/访客基础、学习空间、课程、任务、日历、笔记、文件、专注、AI 基础、IndexedDB/outbox/同步、基础统计 | U1 全链路、离线重连、权限与数据完整性 E2E 通过 |
| 2 | 学习知识与评测 | 知识检索/RAG、PDF 注释、错题、题库、考试、成绩、间隔复习、知识掌握证据 | U2 备考闭环，AI 来源和评分不确定性可见 |
| 3 | 智能学习引擎 | Agent 编排、AI 长期记忆、自适应教学、复杂规划、学习分析与风险预测 | 模型路由/隐私/预算/权限及教学模式测试通过 |
| 4 | 智能日程与自动化 | 高级日历、通知、多渠道调度、规则引擎、自然语言自动化、工作流测试 | 幂等、审批、循环防护、预算硬上限通过 |
| 5 | 多模态、迁移、成长与作品集 | 录音转写/OCR/手写适配、迁移中心、目标/习惯/游戏化、成果导出 | 迁移预览回滚、原件保护、作品来源验证 |
| 6 | 扩展平台与轻量协作 | 插件 SDK/权限沙箱、Webhook、第三方连接器、共享/评论/任务分配 | 插件隔离与成员权限测试通过 |
| 7 | 运维与产品成熟化 | 完整可观测性、存储生命周期、发布渠道、备份恢复、升级中心、深度性能优化 | 安全/性能/恢复演练与多端视觉验收 |

## 阶段 1 内部里程碑（推荐依赖顺序）

- **1.1 基础身份与数据**：访客、本地空间、数据库 schema、API contract、权限基础、IndexedDB。
- **1.2 课程与任务**：课程/学期、任务 CRUD、子任务、引用关系、基础日历事件。
- **1.3 笔记、文件与专注**：Markdown 笔记、文件上传、专注会话、学习日志。
- **1.4 AI 与学习规划**：可配置云端/本地模型、隐私网关、基础问答与可确认的任务建议。
- **1.5 同步与闭环验收**：持久 outbox、增量同步、冲突界面、统计、端到端全链路、离线恢复。

**注意**：阶段 1 中的同步“基础设施”必须能实际处理核心实体，不是只建立空接口；复杂跨设备冲突算法可在后续强化，但不得静默丢数据。

## 阶段通用执行协议

1. 读取 `PROJECT_STATE.md`，列出真实状态、依赖、风险。
2. 制定不超过一个可验收里程碑的执行计划；涉及重大架构变化先提案。
3. 实现真实代码与迁移、测试、文档；运行验证。
4. 提交启动步骤、测试证据、截图、已知问题、变更摘要。
5. 更新状态文件并**停下等待用户验收**。

## 阶段 0 待决 ADR（需证据后决定）

包管理器与 monorepo 工具、Node.js LTS 具体版本、Next.js 具体版本、ORM/迁移、身份方案、IndexedDB 库、同步版本策略、任务队列、向量检索/全文检索、对象存储、插件执行沙箱。不得凭个人偏好在未测试前随意固定。
