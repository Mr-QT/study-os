# 部署、监控、存储、成本与版本生命周期

## 环境
- Windows + WSL2 + Docker Desktop 为主要开发环境；本地 PowerShell 脚本辅助检查。
- dev/staging/prod 配置隔离；Docker Compose 为初期自托管基线；云端部署保持可迁移。
- `.env.example` 仅放占位符；所有密钥使用环境变量/密钥管理，不提交仓库。

## 监控与诊断
- API 延迟/错误率、前端 Web Vitals、数据库连接/慢查询、Worker 队列、同步冲突率、AI Token/费用、插件故障、备份状态。
- 结构化日志 + correlation ID；按需 OpenTelemetry；可选自托管监控栈。敏感字段脱敏，诊断收集最小化。
- 系统健康中心提供状态、告警、失败重试与恢复操作；不要以健康页面取代真实报警机制。

## AI 费用（第 37 项 B）
- 每日/月预算、模型/Agent/空间用量、智能路由、低成本模型、本地回退、缓存和预算阈值。
- 自动化调用在可信执行层强制预算上限和重试上限；不要求建设企业级账务平台。
- 成本是估算，模型提供商账单为准；模型价格可配置且标注更新时间。

## 存储生命周期
- 本地/云端容量分开计量；按空间/类型/文件大小统计；哈希去重与引用检查；缓存/归档/回收站/恢复。
- 自动清理仅可用于可重建缓存；删除原始学习资料需要明确授权和影响预览。

## 版本与发布
- 语义化版本、CHANGELOG、CI/CD、功能开关、环境隔离、插件 API 兼容性和离线客户端版本协商。
- 数据库迁移先备份后执行并校验；不可逆迁移依靠备份恢复，而非虚假的代码一键回滚。
- PWA 更新应避免旧缓存与新 API 不兼容；提供兼容窗口与升级提示。

## 备份恢复
明确 RPO/RTO 目标由实际部署资源决定；至少验证 PostgreSQL、文件资产、密钥配置与必要的本地数据导出。定期演练，保存可审计结果。

## 通知限制
Web Push/邮件等需要权限、服务器和供应商配置；iOS PWA 后台执行能力有限，不能保证在应用关闭时靠浏览器定时器送达。
